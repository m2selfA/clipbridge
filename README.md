# ClipBridge

一个 Windows 优先的轻量局域网图片剪贴板同步器，使用 Rust + `windui`。

## 当前 MVP

- 使用 Windows 自带 `Win+Shift+S` 截图，不依赖 ShareX。
- 监听系统剪贴板中的 `CF_DIB` / `CF_DIBV5` 图片，并校验 DIB 头部、尺寸、位深和压缩字段。
- 仅当剪贴板是“图片-only”内容时同步；如果同时包含文本、HTML/RTF、文件拖放或 OLE/DataObject 等对象格式，即使存在 DIB 预览也会忽略，避免普通文字/Office/文件复制被误判为图片。
- 使用进程内消息窗口作为剪贴板 owner，遵循 Win32 `OpenClipboard` / `EmptyClipboard` / `SetClipboardData` 所需的所有权规则。
- 读写系统剪贴板时自动重试短暂的占用/拒绝访问（最多约 5 秒），避免截图工具或剪贴板管理器瞬时持锁导致同步失败；最终失败时记录当前占用窗口的 HWND/PID 诊断信息。
- 自动同步到已配置的局域网设备。
- 对端收到后直接写入本机剪贴板，可立即 `Ctrl+V`；接收端写入成功后返回加密确认，发送端仅在收到确认后记录为已同步。
- 传输序列号具有有限时间窗口的重放保护，远端写入失败会返回否定确认并自动重试。
- 入站 TCP 连接、剪贴板事件队列、重放缓存和发现设备缓存均有上限，避免异常局域网设备耗尽资源。
- 系统托盘、启动隐藏、关闭到托盘、`Ctrl+Shift+V` 唤起窗口。
- 传输内容使用共享密钥进行 ChaCha20-Poly1305 加密。
- 使用图片内容 SHA-256 哈希和远端标记防止设备之间互相回环同步。
- 每个目标设备记住最近一次成功同步的图片哈希；Win+V 重复选中同一历史图片时不会再次发送。哈希不包含 DIB 格式标签，避免同一图片因 `CF_DIB` / `CF_DIBV5` 变化而重复同步。

## 构建

```powershell
cargo check
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --release
```

Release 构建产物位于 `target/release/clipbridge.exe`。

## GitHub Actions 发布

`.github/workflows/ci-release.yml` 提供 Tag 发布流程：

- 普通分支推送、Pull Request 和手动运行不会触发 CI，避免消耗运行额度。
- 仅推送 `v*` Tag（例如 `v0.2.0`）时，在 `windows-2022` runner 上执行格式检查、Clippy、测试并构建 `x86_64-pc-windows-msvc` 二进制。
- Release 构建使用静态 MSVC CRT，并将 PE OS/subsystem 版本设置为 `10.0`，目标为 Windows 10 x64。
- GitHub Release 自动附带 `.exe`、`.zip` 和 `SHA256SUMS.txt`；同时保留 Actions artifact。

发布示例：

```powershell
git tag v0.2.0
git push origin v0.2.0
```

## 界面设计

主窗口参考 `wind-ui-rust` 的 `settings`、`theming`、`tray`、`i18n` 示例进行了重构：

- 无边框自绘标题栏，保留窗口拖动、最小化、最大化和关闭。
- 默认英语，标题栏提供 `中文` / `English` 切换按钮；译文使用 windui `Locales` / `t!`，切换时即时刷新布局。
- 将高频的运行状态和三步使用方式固定在滚动区域上方，打开窗口即可看到。
- 将附近设备作为主操作区；低频的网络同步与设备安全合并到默认折叠的「Advanced settings」中，减少视觉噪音。
- 使用 `Theme` / `Role` 角色色、状态徽章、步骤卡片和语义色，保持清晰层次。
- 标题栏和托盘统一使用 ClipBridge 品牌图标，并支持明暗主题切换。

## 界面语言

- 默认语言为 English。
- 点击窗口标题栏右侧的语言按钮即可切换到中文；再次点击可切回 English。
- 界面标题、按钮、托盘菜单以及运行状态/错误状态都使用同一套语言资源；切换语言时当前状态会立即重新渲染。
- 后台线程不再直接发送中文状态字符串，而是发送结构化状态事件；包括监听、同步、配对、防火墙和剪贴板错误状态。技术错误详情中的常见中文前缀也会随语言切换翻译。
- 当前内置 `locales/en.toml` 与 `locales/zh-CN.toml`，新增语言可按 windui i18n 格式扩展。

## 自动发现与配对

借鉴 Clipboard Remote / LocalSend / KDE Connect / DecentPaste 的交互模式，实现了无需手动填地址的配对流程：

- **自动发现**：后台通过 UDP 广播（端口 `45822`）每 3 秒公告本机设备名与指纹，同网段设备自动出现在「附近设备」列表；接收端忽略本机回环公告，并对同一来源限频，避免旧版本或异常设备造成广播风暴和 CPU 自旋。
- **信任式配对**：在一侧点击「配对」后，另一侧会显示配对请求与 6 位确认码；双方核对确认码后点击「接受配对」即完成。
- **单端口协议复用**：配对请求与图片同步共用 TCP `45821`，通过 `CBPR` / `CB01` 帧标签分发，不额外启动配对服务，也不会重复绑定端口；图片同步使用 `CBOK` 加密交付确认。
- **版本要求**：启用交付确认后，参与同步的设备应全部更新到同一版本；旧版本不会返回 `CBOK` 确认。
- **独立会话密钥**：每次配对生成独立的 32 字节会话密钥，双方持久化到本地配置；后续图片同步使用该密钥加密。
- **可信介绍自动配对**：如果 A 已分别与 B、C 直接配对，A 会通过各自已有的加密会话，把 B/C 的身份、地址和稳定派生的 B-C 会话密钥互相介绍给双方；B 与 C 无需再次输入确认码即可建立配对。
- **介绍边界**：只有直接配对设备可以发起介绍；通过介绍得到的设备不会继续向第三方转介绍，避免无限信任扩散。直接配对记录也不会被自动介绍覆盖。
- **离线重试**：介绍同步在直接配对完成后触发，并每 15 秒重试，设备暂时离线时重新上线仍可完成自动配对。
- **地址维护**：设备重新公告时会刷新已配对设备的 IP/端口；配对请求同时携带发起方服务端口，避免不同端口配置写错地址。
- **设备撤销**：设备列表中的「忘记」会删除设备会话密钥；忘记直接介绍者时，其介绍出的间接配对也会一并撤销。
- **兼容旧模式**：手动填写的地址仍使用共享密钥（`key_hex`），旧配置文件自动迁移；配置保存采用临时文件替换，避免进程中断造成半写入。

状态流转：`Discovered → Pairing → Awaiting confirmation → Trusted`；确认码由双方身份指纹与随机 nonce 推导，超时未确认自动失败。

自动介绍的安全含义：A 对 B、C 都是可信设备，因此 A 的配对行为会授予 B 与 C 互相同步图片的权限。不要把不可信设备与 A 配对；如需更严格的隔离，应关闭或移除自动介绍形成的 `introduced_by` 配对记录。

## 首次配对

1. 在每台机器上运行一次程序；同网段设备会自动出现在「附近设备」。
2. 在其中一台点击「配对」，另一台核对 6 位确认码后点击「接受配对」。
3. 配对完成后截图即可自动同步。

也可以继续使用手动方式：

4. 打开 `%APPDATA%\\ClipBridge\\config.toml`。
5. 将所有机器的 `key_hex` 设置为同一个 64 位十六进制密钥，并在 `peers` 中填写其他机器地址：

```toml
bind_addr = "0.0.0.0:45821"
peers = ["192.168.1.20:45821"]
key_hex = "替换为同一组 64 位十六进制密钥"
```

6. 首次启动时，程序会检查 `ClipBridge TCP 45821` 与 `ClipBridge UDP 45822` 防火墙规则；缺少规则时自动请求 UAC。用户批准后，程序自动创建入站放行规则；取消 UAC 后程序仍会启动，但设备发现或配对可能不可用。
7. 截图后，其他机器可以直接粘贴图片。

如果设备能发现但配对请求到不了某台机器，重点检查该机器的**入站 TCP 45821**；Windows 将网络标记为 Public 时，默认通常会阻止入站连接。可用以下命令诊断规则状态：

```powershell
Get-NetFirewallRule -DisplayName "ClipBridge TCP 45821","ClipBridge UDP 45822"
```

配置窗口中的“设备地址”和“共享密钥”也可以直接修改并保存。

## 当前边界

- 第一版仅支持 Windows。
- 只支持同一局域网或已有 VPN/虚拟局域网；没有云端中继。
- 当前同步图片，不同步文本和文件。
- 当前直接传输 Windows DIB 数据，后续可增加压缩、历史记录和自有区域截图。
- 远端图片只有成功写入本机当前剪贴板后才加入回环抑制记录，写入失败不会吞掉后续重试；写入远端图片时会按 Windows 剪贴板语义替换目标机当前剪贴板内容，这是图片同步的预期行为。提交图片数据失败时会重试一次，并尽力恢复原先的图片-only 剪贴板；对于文字/文件等非图片对象，Windows 没有通用的无损回滚接口。
- 发现广播未加密（仅含设备名/指纹/端口），配对确认码通道未做加密握手；对高安全场景建议在可信网络使用，后续可升级 Noise XX 握手。
- 目前已在本机验证进程启动、TCP/UDP 端口监听、自动防火墙模块编译、全局热键、关闭到托盘、配置生成与发现/配对界面渲染；两台真实机器之间的发现/配对/同步闭环仍需现场验证。
